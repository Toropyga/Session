## Общие понятия

Класс Session - это библиотека для работы с сессиями в PHP.
Для работы необходимо наличие PHP версии 7.4 и выше (идентификаторы сессии генерируются с помощью `random_bytes()`, а также используются типизированные свойства и `declare(strict_types=1)`).
Может сохранять данные сессии пользователя в базе данных.
Работает с БД MySQL и Postgre.
Автоматически создаёт таблицу в БД, если она не существует, для хранения данных сессии.


## Установка
Рекомендуемый способ установки библиотеки с использованием [Composer](http://getcomposer.org/):

```bash
composer require toropyga/session
```

> Минимальная версия PHP: 7.4+


## Настройка
Предварительная настройка параметров по умолчанию может осуществлятся или непосредственно в самом классе, или с помощью именованных констант.
Именованные константы при необходимости обявляются до вызова класса, например, в конфигурационном файле, и определяют параметры по умолчанию.
* SE_LIVETIME - время "жизни" простой (гостевой) сессии (сек.)
* SE_LIVETIME_REM - время "жизни" сохранённой сессии (сек.)
* SE_NAME - имя сессии
* SE_USEDB - использовать БД (true|false)
* SE_DB_TYPE - тип базы данных для хранения сессий (mysql|postgre); поддержка postgre экспериментальная
* SE_SECURE - параметр безопасности "secure" для COOKIE (true|false)
* SE_HTTPONLY - параметр безопасности "httponly" для COOKIE (true|false)
* SE_SAMESITE - порядок кроссдоменной передачи куки (lax|strict|none)
* SE_USE_TMPL - создать специальную директорию (папку) для хранения сессионных файлов (true|false)
* SE_TMPL_NAME - Имя директории для хранения сессии
* SE_USE_SERVER_NAME - использовать имя сервера при создании директории (true|false)
* SE_USE_SDIR - использовать стандартную папку для хранения сессий (true|false)
* SE_LOG_NAME - имя файла в который сохраняется лог
* SE_DEBUG - включить или выключить отладку и запись в лог
* SE_STRICT_IP - сбрасывать данные сессии, если IP-адрес клиента изменился в процессе сессии (true|false, по умолчанию: false). По умолчанию отключено, так как у легитимных пользователей IP может меняться между запросами (мобильные сети, корпоративные прокси, CDN).
* SE_NO_CACHE_HEADERS - отправлять ли заголовки `Cache-Control` / `Expires` / `Pragma` "no-cache" при каждом запросе, инициирующем сессию (true|false, по умолчанию: true). Отключите, если ваше приложение самостоятельно управляет заголовками кэширования.

> **Замечание по безопасности (v3.1.0):** идентификаторы сессии теперь генерируются с помощью `random_bytes()` (криптостойкий генератор случайных чисел) вместо хеша от текущего времени, а идентификатор сессии, полученный из cookie клиента, принимается только если строго соответствует шестнадцатеричному формату — иначе генерируется новый. Данные сессии, загруженные из базы данных, десериализуются с параметром `allowed_classes => false`, что предотвращает PHP Object Injection, а директории для файлов сессий теперь создаются с правами `0750` вместо `0777`.


## Публичные методы

### `sessionInit(): void`
Инициализирует сессию: подключается к базе данных (если включён `SE_USEDB`) и создаёт таблицу сессий, если она ещё не существует, затем запускает PHP-сессию и, при использовании БД, загружает сохранённые данные сессии в `$_SESSION`. Обычно это первый метод, который вызывается после создания объекта класса.

### `setSession(): bool`
Сохраняет текущие данные `$_SESSION` в базу данных (вставка или обновление записи в зависимости от того, существует ли уже строка с текущим ID сессии). Автоматически вызывается из деструктора, поэтому вручную обычно вызывать не требуется — но метод доступен, если нужно принудительно сохранить данные немедленно (например, сразу после изменения `$_SESSION['user_id']` при входе пользователя, перед редиректом). Возвращает `false`, если сессия ещё не инициализирована или ID сессии отсутствует/некорректен.

### `setDebug(bool $debug = false): void`
Включает или выключает отладочное логирование. При включении внутренние шаги (путь к сессии, ID сессии, загрузка/сохранение данных и т.д.) записываются и могут быть получены через `getLogs()`.

### `getLogs(): array`
Возвращает собранные отладочные логи в виде массива с двумя ключами:
* `log` - массив сообщений лога
* `file` - имя файла лога (`SE_LOG_NAME`), в который они предназначены для записи

### `setMyCookie(string $name = '', string $value = '', int $live_time = 0, string $domain = '', ?bool $secure = null, ?bool $http_only = null, ?string $samesite = null): bool`
Устанавливает cookie с теми же параметрами безопасности (`secure`, `httponly`, `samesite`), что настроены для сессии. При обычной работе cookie сессии уже отправляется автоматически через `sessionInit()`/`getSession()`, поэтому вызывать этот метод для самой сессионной cookie не требуется. Метод предоставлен как публичная утилита для случаев, когда нужно вручную выставить дополнительную cookie — например, переустановить cookie "запомнить меня" с другим временем жизни или доменом.

Параметры:
* `$name` - имя устанавливаемой cookie
* `$value` - значение cookie. Если не указано (пустая строка), используется текущий ID сессии (`$this->sid`)
* `$live_time` - время жизни cookie в секундах, отсчитываемое от текущего момента. Если не указано (`0`), используется время жизни гостевой сессии по умолчанию (`SE_LIVETIME` / `$session_live_time`)
* `$domain` - домен, для которого выдаётся cookie. Если не указан, определяется автоматически из `$_SERVER['SERVER_NAME']`
* `$secure` - переопределяет флаг "secure" (cookie отправляется только по HTTPS). Если `null`, используется значение по умолчанию для класса (`SE_SECURE`)
* `$http_only` - переопределяет флаг "httponly" (cookie недоступна из JavaScript). Если `null`, используется значение по умолчанию для класса (`SE_HTTPONLY`)
* `$samesite` - переопределяет политику SameSite (`lax`|`strict`|`none`). Если `null`, используется значение по умолчанию для класса (`SE_SAMESITE`)

Возвращает `true` при успехе, `false` если cookie установить не удалось (как и у стандартной функции PHP `setcookie()`).

### `__construct()`
Считывает конфигурацию из именованных констант (см. раздел [Настройка](#Настройка)) и подготавливает хранилище сессий (определения таблиц БД, директорию для файлов сессий), но саму сессию ещё не запускает.

### `__destruct()`
Автоматически вызывает `setSession()` для сохранения данных сессии в базу данных при уничтожении объекта в конце выполнения скрипта.

```php
require_once("vendor/autoload.php");
```

```php
$SE = new Toropyga\Session();
```

## Пример использования

```php
$SE = new Toropyga\Session();
$SE->setDebug(true); // включить отладку
$SE->sessionInit();
```
